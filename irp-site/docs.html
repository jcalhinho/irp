IRP — Intent Rendering Protocol

Le protocole qui remplace le HTML par des intentions. Le navigateur génère l'interface via IA locale.

v1.1 Streaming SEO Prerender

Qu'est-ce qu'IRP ?

IRP (Intent Rendering Protocol) est un protocole web qui inverse le modèle client-serveur. Au lieu d'envoyer du HTML/CSS/JS, le serveur envoie une intention (JSON ~2KB). Le navigateur, via un agent IA embarqué, génère l'interface optimale pour cet utilisateur, cette machine, ce contexte.

// Le serveur envoie ceci (2KB) : { "irp": { "version": "1.1", "intent": "show_product", "data": { "name": "MacBook Pro 16", "price": { "amount": 2799, "currency": "EUR" } }, "actions": [{ "id": "add_to_cart", "label": "Ajouter au panier", "type": "primary" }] } } // Le navigateur génère ceci (13KB) : // → HTML5 + CSS inline + JS inline + SVG inline // → Adapté à l'écran, au thème, à l'accessibilité de l'utilisateur

Comment ça marche

  1. Le client demande une page (GET /product/123)
  2. Le serveur répond avec un IRP JSON (Content-Type: application/irp+json)
  3. Le client détecte le contexte (écran, thème, a11y, réseau, batterie)
  4. Le Model Router choisit le meilleur renderer IA disponible
  5. L'IA génère le HTML/CSS/JS adapté au contexte
  6. Le DomBuilder sanitize et injecte le résultat
  7. Le rendu est caché dans IndexedDB pour les visites suivantes
💡 Bot detection
Les bots (Googlebot, Bingbot) reçoivent du HTML statique prerenderisé côté serveur. Le SEO est préservé.

json { "irp": { "version": "1.1", "intent": "show_product", "data": { ... }, "constraints": { "must_show": ["name", "price"], "priority": "conversion", "content_type": "commercial" }, "context_hints": { "cacheable": true, "ttl": 3600, "streamable": true }, "actions": [ { "id": "add_to_cart", "label": "Ajouter au panier", "type": "primary", "href": "/cart/add/123", "method": "POST" } ], "metadata": { "title": "MacBook Pro 16 — 2799€", "description": "Le MacBook Pro 16 pouces...", "lang": "fr", "og_type": "product" }, "seo": { "prerender": true, "json_ld": { "@type": "Product", ... } } } }

Streaming v1.1

Le client peut demander un rendu en streaming via SSE (Server-Sent Events).

Requête

Accept: text/event-stream X-IRP-Context: {"device":"desktop","theme":"dark","lang":"fr"}

Réponse

sse event: irp data: {"irp":{"version":"1.1","intent":"show_product","data":{...}}} event: chunk data: {"delta":""} event: chunk data: {"delta":"

MacBook Pro 16

"} event: done data: {"renderer":"SGP API","bytes":4523}
⚠️ Support
Le streaming n'est supporté que par le renderer SGP API. Les renderers locaux (Chrome API, WebLLM, LFM3) génèrent atomiquement.

SEO & SSR v1.1

IRP résout le problème SEO en détectant les bots via User-Agent et en servant du HTML statique prerenderisé.

Bot detection

http # Bot User-Agent: Googlebot/2.1 → Content-Type: text/html → X-IRP-Prerendered: true # Client normal User-Agent: Mozilla/5.0 ... → Content-Type: application/irp+json

Le HTML prerenderisé inclut :

  • <title> et <meta name="description">
  • Open Graph tags (og:title, og:description, og:type)
  • Twitter Card tags
  • JSON-LD structured data (schema.org)
  • Contenu sémantique HTML5 (h1, h2, p, ul, table)

Cache

Client (IndexedDB)

Le client cache le HTML rendu dans IndexedDB. La clé inclut : path + intent + data_id + contexte (theme, lang, device, viewport, a11y).

TTL

Configurable via context_hints.ttl (défaut: 3600s). context_hints.cacheable: false désactive le cache.

Extension navigateur

L'extension Chrome/Firefox intercepte les réponses application/irp+json sur n'importe quel site.

  1. Ouvrir chrome://extensions
  2. Activer "Developer mode"
  3. "Load unpacked" → irp-extension/

L'extension patche fetch() et XMLHttpRequest automatiquement.

Sécurité

Sanitization

Le client sanitize tout le HTML généré avant injection :

  • Supprime <iframe>, <object>, <embed>
  • Supprime <script src="..."> (scripts externes)
  • Supprime <link rel="stylesheet"> (CSS externe)
  • Supprime les event handlers inline (onclick, onload)
  • Supprime les javascript: URLs
  • Remplace les <img src="http..."> par des placeholders

Proxy

Le proxy SGP ne expose jamais la clé API au client. Rate-limiting recommandé (10 req/min/IP).
